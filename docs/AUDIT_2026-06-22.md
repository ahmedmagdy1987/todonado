## 2. FLAGGED — HIGH (decide before changing; most need a migration / auth change)

### H1 — `resolve_login_email` is an unauthenticated username→email enumeration RPC (no rate limit) · FACT
- **Where:** `supabase/migrations/20260616120000_accounts_username.sql:108-124` (SECURITY DEFINER, `grant execute … to anon`); called pre-auth from `src/features/auth/api/accounts.ts:21` and `LoginPage.tsx:65-69`.
- **Impact:** Any holder of the public anon key can POST a guessed username to `/rest/v1/rpc/resolve_login_email` and get back the account's **real login email** (read from `auth.users`, which RLS otherwise hides). The migration's own header calls gateway rate-limiting a "REQUIRED follow-up" — it does not exist in the repo (`config.toml` `[auth.rate_limit]` covers only GoTrue, not the RPC path). Bounded by: exact-match only (no listing), usernames are nullable and not shown publicly.
- **Recommended fix (do NOT auto-apply — auth change):** replace the email relay with a **server-side sign-in Edge Function** (accept `{identifier, password}`, return a session, never the email — exactly what the migration recommends). Short term: enable Turnstile/captcha (the `[auth.captcha]` block in `config.toml` is commented out) + a per-IP limit on the RPC. Treat as a launch blocker.

### H2 — Monthly/yearly recurrence permanently drifts off month-end · FACT
- **Where:** `src/features/tasks/recurrence.ts:42-60, 93-107, 114-137`; spawn at `api/completeTask.ts:60-65`; schema `20260605090000_task_recurrence.sql` has **no anchor/dtstart column**.
- **Impact:** A task on the 31st, once it lands on a short month (e.g. Feb 28), **anchors on the clamped date forever** — it never returns to the 31st/30th. "Monthly on the 31st" silently becomes "the 28th."
- **Recommended fix (needs migration):** store the original anchor day (a `recurrence_anchor`/dtstart column) and compute each occurrence from the anchor, not from the last (clamped) occurrence.

### H3 — Focus timer trusts the device clock; skew can freeze a sprint at 0 or instantly auto-complete it · FACT
- **Where:** `src/features/focus/timer.ts:16-20` (`elapsedSeconds` mixes server `started_at` with client `Date.now()`); `components/RunningView.tsx`.
- **Impact:** Elapsed = `Date.now() − started_at(server)`. If the device clock is behind the server, elapsed is negative → frozen at 0; if ahead, the sprint can auto-complete immediately. (Drift-resistant against *throttling*, not against a *wrong clock*.)
- **Recommended fix (non-trivial):** anchor to a single clock — e.g. capture a client `performance.now()` baseline at start, or fetch a server-time offset once and correct `Date.now()`. INFERENCE on real-world frequency; FACT on the code path.

### H4 — Open, unscheduled tasks in an **archived** project become invisible (violates the pinned "no task ever invisible" invariant) · FACT
- **Where:** `selectors.ts:28-49` (Inbox = `project_id == null` only); `ProjectsPage.tsx:124-148` (archived projects render with **no open link**, only "Restore"); `useProjects.ts:91-98` (archive just flips `status`).
- **Impact:** A task with `project_id` → an archived project is not in Inbox (has a project), not in Today (unscheduled), and its project can't be opened → **stranded in the UI**. Related: **M6** (a recurring task in an archived project respawns back into it).
- **Recommended fix (product decision — flagged, not applied):** simplest safe option is to make archived projects **openable** (a view link to `/projects/:id`, which already renders regardless of status) so their tasks aren't stranded; or surface "tasks in archived projects" in Inbox. Pick the intended behavior.

### H5 — `completeTask` is non-atomic: the done-UPDATE commits, then the recurrence-INSERT can fail → broken recurrence chain · FACT
- **Where:** `src/features/tasks/api/completeTask.ts:40-69` (compare-and-swap UPDATE at 40-58, spawn INSERT at 64-65); `useTaskMutations.ts:90-114`.
- **Impact:** Two separate statements, not a transaction. If the next-occurrence INSERT fails after the completion UPDATE commits, the task is done but **the next occurrence is silently lost** — the recurring series ends.
- **Recommended fix (needs migration):** move complete-and-spawn into a single Postgres `SECURITY INVOKER` RPC (one transaction). Interim safe mitigation: surface the INSERT failure to the user (toast) so the loss isn't silent — see H6/M9.

### H6 — Mutation failures roll back silently with **zero** user feedback · FACT — *(related fix F1 shipped for fetch errors; mutation feedback flagged)*
- **Where:** optimistic mutations in `useTaskMutations.ts` (and siblings) roll back `onError` with no toast; fire-and-forget `.mutate()` callers across the app.
- **Impact:** A captured/edited task that fails to persist (offline, RLS, 500) **visually reverts with no message** — the user thinks it saved. (F1 fixed the *read* side; this is the *write* side.)
- **Recommended fix (safe, but broader than a blind edit — flagged):** add a global `MutationCache.onError` (via a small toast bridge so the React-less `queryClient` can reach `ToastProvider`) or per-call `onError` toasts. Recommend doing this as a focused follow-up.

## 3. FLAGGED — MEDIUM

- **M1 · FACT — `focus_sessions` can reference another workspace's `task_id`** (no co-location guard like `tasks` has). `20260604090000_focus_sessions.sql:11-12,42-45`. Cross-workspace *linkage* (RLS still gates row access). Fix: add a `WITH CHECK` co-location guard (migration), mirroring `20260607090000_task_workspace_integrity.sql`.
- **M2 · FACT — `username_available` is a precise anon account-existence oracle.** `accounts_username.sql:91-103,124`. Same rate-limit gap as H1. Fix: captcha/rate-limit; acceptable risk if H1 is addressed together.
- **M3 · INFERENCE — credential-spray oracle:** verbatim `signInWithPassword` error + min-6 password + enumerable emails + no app-layer lockout. `LoginPage.tsx`, `config.toml`. Fix: generic auth errors + captcha + stronger password floor (server-side).
- **M4 · FACT — overbooking suggestion evicts the *largest* task** to clear even a tiny overage (tie-break favors biggest effort). `capacity.ts:92-95`. This is *documented* behavior ("move fewer tasks") but undercuts "protect the right work." **Product decision** — flag, not bug.
- **M5 · FACT — template "new project" apply is non-transactional:** a mid-sequence section/task failure leaves an **orphaned half-built project** (no rollback). `templates/apply.ts:67-108`, `useApplyTemplate.ts`. Fix: a transactional apply RPC, or client-side cleanup (delete the project) on failure.
- **M6 · INFERENCE — recurring task in an archived project respawns into the archived (unreachable) project.** Ties to H4. Fix together.
- **M7 · FACT — optimistic placeholder ids (`optimistic-<uuid>`) can be targeted by a follow-up mutation** before the real row reconciles (no-op/error/row visually disappears). `useTaskMutations.ts`, `useSubtasks.ts`, wellness `createItem`. Fix: disable per-row actions while a create is pending, or reconcile the real id in `onSuccess` (as the wellness `markTaken` fix already does).
- **M9 · FACT — focus session start is fire-and-forget:** the UI claims a session started even if the insert fails. `focus/components/SetupView.tsx:41-48`, `useFocusSessions.ts:40-54`. Fix: add `onError` (await/handle the mutation). Part of the H6 theme.
- **M10 · FACT — template "apply to Today/Inbox" assigns positions `0..N`,** colliding with existing tasks (lands at top / interleaves). `templates/apply.ts:85-105`. Minor ordering; consistent with the app's existing `position: list.length` pattern (**L7**). Fix: base positions after the current max.
